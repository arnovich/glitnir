# Glitnir 0.1.13 release notes

Changes since 0.1.12. Publication follows verification of the exact candidate
assets and fresh installation on macOS and Linux.

## Review while reading

- A sticky review bar keeps Previous, Item X of N and Next together. Its jump
  list explains why each claim needs review; the bar disappears when the queue
  is empty.
- Notebook, Source and Explore sit in a centred view switcher. Connection and
  saved-result status have their own line below the filename, whose tooltip
  shows its full path.
- A More menu groups History, Export HTML and Follow live edits.

## Claim checks and proof goals

- Selecting a claim opens the Inspector. Check up to this claim checks the saved
  file through that declaration; Inspect proof records its tactic goals in place.
- Expand proof steps opens the full view and reuses a current recording. Return
  restores the claim and Inspector. Expansion is disabled during project checks.
- Inline results foreground the goal, fold repeated context, and show compact
  numbered step headers. Full tactic code scrolls horizontally; expanded sections,
  keyboard focus and reading position survive polling.
- Source and toolchain provenance is available under Recording details. Recorded
  goals describe Lean elaboration and never change a claim's proof-check status.

## Visible progress

- Active checks and proof recordings remain visible across Notebook, Source and
  Explore, including when the Inspector is closed.
- Progress identifies the target, current stage and elapsed wait, with Stop or
  Cancel nearby. Competing run actions are disabled while work is active.
- Proof recordings report the source line reached, lines remaining and recorded
  tactic count after each command. These are source-traversal counters, not an
  estimate of time remaining or proof completion.

## Distribution

Extension, backend and optional Forseti plugin are versioned 0.1.13. The universal
thin VSIX still requires Python 3.12+ and Lean 4.35.0; it includes neither Python,
Lean nor Mathlib. The plugin retains its backend requirement `>=0.1.10,<0.2`.

Verify the candidate manifest, SHA256SUMS and GitHub asset digests, then test the
exact downloaded assets on macOS and Linux. Publish the verified draft without
rebuilding it or changing its tag or assets. These notes are not a validation
receipt.
